## 1. Verdict

**Not ready to ship yet. Conditional go once the P1s are fixed.** The engine is functionally strong. 40 of 47 acceptance
tests pass end to end. Romaji, deinflection, kana folding, markup stripping, the no-word-match state, deep links, the error card with Retry,
IME and Hide English all work. The cold-load fallback also works. 5 tests fail and 2 pass only partly. The blockers:

1. **Performance (P1).** First search misses its budget by a wide margin. With Fast 4G and CPU ×4, p75 is **2.2 s** against a 1.5 s budget. On desktop with no throttling it is **0.86 s** against 0.5 s.
   The cause: the worker fetches the 7 shards **one after another** and answers no query until all of them are in. The design
   in §4.4 called for parallel or progressive loading.
2. **Category chips (P1).** Tapping a chip keeps `q`, so the list is intersected with the query. "Degree / Extent · 45" opens **1** point (T-12 fails).
3. **Ranking (P1).** Two rules bury what a learner is looking for:
   (a) Grammar keys contained inside the query flood kana queries: `わかります` shows 8 `Vます-form` rows before the vocab entry, which sits ~1,400 px down on a phone.
   (b) Ordering by current level first pushes core N5 items behind "Show all" (T-06, T-37, T-39 fail).

Everything else is P2/P3 polish: scroll restore, a history race, the blank zero state in the category view, and the modal shortcut guard.

## 4. Accessibility pass

- **Keyboard:** `/` and `Ctrl+K` focus the field from any non-input target ✓. `/` typed inside "Filter this lesson…" stays in that field ✓.
  `↑`/`↓` move `aria-activedescendant` across groups in visual order, include the "Show all" footer, and wrap ✓. `Enter` on the footer
  expands it ✓. `Enter` opens the row ✓. `Esc` clears the query, and a second `Esc` leaves search ✓ (but see BUG-07). Rows are not Tab stops (combobox pattern, as specified).
- **Focus visibility:** every Tab stop on `/search` showed a ring (outline or box-shadow). Header ring is white on indigo. Sample: `qa/focus-visible-sample.png`.
- **Roles:** the input is `role=combobox` with `aria-expanded`, `aria-controls="search-results"`, `aria-autocomplete=list` and `aria-activedescendant` ✓.
  `#search-results` is `role=listbox`. Each group is `role=group` labelled by an `<h2>` ✓, rows are `role=option aria-selected` ✓, and there are 20 `lang="ja"` spans per page ✓.
  Exceptions: nested links (BUG-15), and modals without a dialog role (BUG-09).
- **Live region:** one `role=status aria-live=polite aria-atomic` region. It announced once after typing paused, not per keystroke ✓.
  Zero results ("No results for zzqx.") ✓, filter change ("Filtered to N3, N2: 5 results…") ✓, error ✓.
- **Contrast:** computed for every visible text node, with oklch converted through a canvas. Only BUG-14 is new. These are pre-existing and outside search: the header subtitle `text-indigo-200`
  4.33, inactive header tabs 4.33, "• Grammar Reference" `text-slate-400` 2.63.
- **Mobile:** the header icon is 40×40. It focuses the input synchronously and opens search mode (`[←] [input] [×]`, 57 px). The input is 16 px (no iOS zoom).
  No horizontal overflow at 390 px (results, tag view, zero state). Row links stretch over the full `min-h-14` row, so the targets are fine.
- **IME** (CDP `Input.imeSetComposition`): typing `t → た → たべ → たべる → 食べる` kept the URL on the lesson page and ran no search until commit.
  One push to `/search?q=食べる` followed ✓. `Enter` while composing is guarded in code (`isComposing` or keyCode 229).
- **Hide English:** meanings render as `••••••••` with sr-only "translation hidden". There is no English leak or highlight. The "English is hidden. Matches are based on meanings." note shows ✓. `qa/hide-english.png`

## 7. UX observations (learner lens; not bugs per se)

1. **Group order by script is too blunt.** "Kana → Grammar first" puts grammar ahead of an exact vocab hit for `わかります`, `よほど` and `たくしー`-like words.
   Pick the first group by best tier: if Vocab has an exact or lemma hit and Grammar only has contains hits, show Vocab first.
2. **Deinflection fan-out is wide.** `かえって` yields 8 deinflected rows (替える, 換える, 代える…), `きた` includes 斬る "behead", and `さけ` gives 3 imperative 咲け rows.
   Consider ranking deinflected candidates by level (N5 first) rather than current level, and dropping imperative for 2-kana inputs. (Teacher to confirm.)
3. **Current-level-first is hard to read.** Even in a pure-level view (`mei`) the kanji list starts mid-way (N3, then N5, then N1). The "(ranked for N3)" hint is subtle. If PM keeps the rule,
   show a level subheading or divider when the order wraps.
4. **Category chips vs typed query** (BUG-02/05): after tapping a chip the learner is in a filtered mode that outlives the next query. Make the active
   function filter more prominent in the results header (not only in the rail), or clear it when the query changes.
5. **"for" returns "No results for for"** but shows two category chips. Fine, but the heading reads oddly. Consider "No word matches · 2 function categories".
6. **Badge colour on vocab and kanji rows** (emerald, rose) matches the sections well, and the collapsed-duplicate row (ちょうど) is clear.
7. **Bundle headroom is gone** (+14.7 of 15 KB). Any further UI work on search needs to move code into the lazy chunk.
