# Global search: UX design spec

Status: draft for UI and data engineering · Inputs: `01-teacher.md`, `02-requirements.md` (primary),
the running app at 1280 px and 390 px (2026-10-31). Story IDs (US-n, T-nn, Q-UXn) refer to `02-requirements.md`.
Data contract owner: `04-data.md`. This doc says **what the UI shows and does**. §7 lists the fields it needs.

---

## 1. Information architecture

### 1.1 Decision: one `/search` page, driven by one persistent header field

Search is a **route** (`/search?q=…`) that renders in the main content area, under the normal header,
on every screen size. There is **no separate overlay palette**. The entry point is a single search field
in the header (`HeaderSearch`). The header sits outside `<Routes>`, so it never remounts. The input keeps
focus and caret while the route changes underneath it.

- **On a lesson page**, the field is empty. The first character typed (or `/`, `Ctrl/Cmd+K`, or a tap on the
  mobile icon) **pushes** `/search?q=<text>`. Focus stays in the same input. To the learner it behaves like
  a palette that opens as a page.
- **On `/search`**, typing **replaces** the history entry (US-11). Opening a result **pushes** the lesson URL,
  so Back returns to the results with the query, filters, expanded groups and scroll position intact.
- **Leaving search**: `Esc` on an empty query, the ← button (mobile), or browser Back all return to the
  lesson you came from, at the same scroll position (US-1). See `useScrollRestore` in §7.1.

**Why not an overlay palette (answers Q-UX1).** An overlay looks less disruptive because the lesson stays
underneath. But it has to share the URL with the lesson (`/n3/grammar/5?q=…` collides with nothing, but then
"open result" has to close the overlay and change route in a single step). Back-button behaviour would split
between the two layers, and mobile needs a full-screen variant anyway. The results also need room: category
chips, three filters, three groups of 8 rows, and "show all". A page gives one renderer, one URL scheme, real
`<a href>` rows (middle-click and copy-link work) and natural Back. It also has no focus trap to get wrong.
The palette *feel* comes from keeping focus in the header field. Cost: lesson scroll must be restored on
return. That is a ~30-line hook, cheaper than background-route overlays.

### 1.2 Placement

| Viewport | Where | Looks like |
|---|---|---|
| ≥ md (768 px) | **Right end of the section-tab row** (`Grammar · Vocabulary · Kanji · Reading Practice ………… [🔍 Search all levels   /]`). The top row is already full at 1280 px (title, level pills, AI and Hide English buttons). The tab row has ~550 px free. | Translucent field on indigo, `w-72 lg:w-80`, `/` kbd hint on the right. |
| < md | **Icon button at the right of the title row** (next to the `N4` badge). The mobile header is already ~225 px tall, and a permanent field would cost one more row. | 40×40 `Search` icon, `aria-label="Search all levels"`. |
| `/search` on < md | The header switches to **search mode**: one row `[←] [input……] [×]`. The title, level pills, AI/English buttons and tabs are hidden. The page is effectively a full-screen sheet. | See wireframe M2. |

### 1.3 Coexistence with level → section → lesson, and recommended moves

| Element | Recommendation |
|---|---|
| **Level switcher (pills)** | **Keep in the header, unchanged.** It stays navigation, not a search filter. On `/search` the pills still navigate to that level's lesson. The search *level filter* is a separate control on the results page, so two meanings never share one control. The `N3` title badge shows the *ranking level* on `/search`: the level of the last lesson visited (`lastLevel` in `useAppStore`, persisted, default N3). |
| **Section tabs** | **Keep.** On `/search`, no tab is active, and clicking one returns to `lastLevel`'s lesson in that section. The search field joins this row on desktop. |
| **Per-lesson filter boxes** (Grammar, Vocab, Kanji banners) | **Keep, but relabel as filters (Q-UX4: yes).** Swap the `Search` icon for `Filter` (lucide `ListFilter`) and use the placeholder "Filter this lesson…", so they never look like the global search. When a filter has **0 hits**, the empty card adds a button **"Search all levels for "…" →"** that links to `/search?q=…`. Arriving with `?focus=` clears the lesson filter, so the target item is never hidden. |
| **Tag browsing** (Q-UX5) | **New, in three places, all landing on `/search?tag=` or `?cat=`.** (1) The `/search` empty state shows "Browse grammar by function" with category chips (primary entry). (2) **Every `TagBadge` on a grammar card becomes a link** to `/search?tag=<id>`, so "show me every *Comparison* point" is one tap from any lesson. (3) A footer link in the Grammar sidebar: "Browse by function →" goes to `/search?type=grammar`. No new top-level tab. |
| **Reading Practice** | **Keep as is.** It is not indexed (PM non-goal). Its in-library filter stays a local filter. The search empty state says "Search covers grammar, vocabulary and kanji". |
| **Header subtitle** "JLPT N5–N1 Interactive Reference & AI Practice" | Keep on desktop. Hide it `< md` (`max-md:hidden`) to win back ~16 px for the icon row. This is optional and cosmetic. |

## 2. Key flows

**F1. Type-ahead → result → lesson → back (T-15, T-44)**
1. On `/n3/grammar/5`, the learner presses `/`. The header field focuses (and the index prefetch starts, §4.1).
2. They type `ものの`. During IME composition, nothing runs. On `compositionend` the URL becomes
   `/search?q=ものの` (push, because it is the first one). The results area renders skeleton rows, then results
   ≤ 100 ms after the last keystroke.
3. Grammar group first (kana query). Row 1, 〜ものの `N2 · L4`, is pre-selected (`aria-activedescendant`).
   The learner presses `Enter`.
4. Navigate (push) to `/n2/grammar/4?focus=n2-grammar-4-1` with `location.state = { fromSearch: '/search?q=ものの' }`.
5. The lesson loads. `useFocusItem` waits for the card with `data-uid="n2-grammar-4-1"`, scrolls it into view
   (`block:'start'`, `scroll-margin-top` clears the sticky header), moves focus to the card (`tabIndex=-1`), and
   plays the highlight (§5.4). The sidebar's active lesson scrolls into view as it does today.
   A **SearchReturnBar** appears at the top of the content column: `← Back to results for "ものの"`.
6. Back (browser, the bar, or `Alt+←`) returns to `/search?q=ものの`. The input is refilled from the URL,
   results come from the warm index, scroll is restored and the previously opened row is selected.

**Q-UX2 answer.** Use **`?focus=<uid>`**, not `#uid`. A hash makes the browser try to scroll before the async
lesson chunk has rendered, and `#…` is already reserved for legacy section shortcuts in `parseLegacyUrl`. The query
param is explicit, testable and harmless if someone shares it: a cold load highlights the item too.
It stays in the URL. Sidebar and tab navigation drop it naturally because they build fresh paths.
**Grammar does *not* auto-open `GrammarDetailModal`** (a deliberate change to US-7, please confirm). The lesson
card already shows title, meaning, structure, explanation and examples. A modal would hide the
lesson context the learner came to see, stack a second `Esc` and a second Back meaning, and make grammar behave
differently from vocab and kanji. The highlighted card's **Deep Dive** button gets the focus ring, so one `Enter`
opens the modal.

**F2. Inflected query (US-3, T-01, T-29, T-30, T-33)**
`待たされた` shows the vocab row 待つ `N5 · L14` in the deinflected tier, with a reason line under the meaning:
`待たされた → 待つ · causative-passive, past（使役受身・過去）`.
**Q-UX6 answer:** show the English terms first and the Japanese grammar labels after them in full-width brackets,
in `text-slate-400`. N3+ learners meet 使役受身 in JLPT books, and N5 learners can ignore it. The line stays visible in
Hide-English mode, because it is metadata, not a translation. Ambiguous forms (`かえって`) show one row per candidate,
each with its own reason line. Lemma-only hits (`わかります` → 分かる) use the short form `→ 分かる (dictionary form)`.

**F3. Function / tag browse (US-5, T-10–T-12, T-14)**
- Typing `comparison` shows a **CategoryChip** above the groups: `▤ Comparison · 17 points →`. Ambiguous words
  (`so`, `but`, `about`) show 2–4 chips side by side, with no guessing.
- Tapping a chip sets `cat=comparison` (replace) and `type=grammar`, keeps `q`, and shows an active filter pill
  `Comparison ×`. The list is ordered by level, then lesson (N5 → N1), and grouped under **level subheadings**
  (`N5 · 2`, `N4 · 3` …) so a reviewer can scan the progression. This is the only view where level subheadings
  replace the type groups.
- From a lesson, tapping a `TagBadge` pushes `/search?tag=degree-extent` with the same layout and no `q`.
- Empty state: a "Browse grammar by function" panel shows the 23 alias categories as chips (counts added once the index
  is loaded), then a collapsed "All tags" disclosure that lists the raw tags by facet (Function · Register · Structure)
  in the facet colours `TagBadge` already uses.

**F4. Empty, short and zero results (US-9, T-39, T-42)**
- **Empty query**: hints ("Try 食べる · taberu · although · ばかり") as clickable examples, then the browse panel. No results.
- **Romaji converted**: when the query was read as romaji, show a quiet line above the groups: `Searching as
  きょうしつ`. If the index offers a deterministic alternative (`kani` → `kan'i` has hits), add
  `Did you mean kan'i?` as a link. No AI, ever.
- **One kana**: a muted note under the counts: "Showing exact matches only. Type 2+ characters for more."
- **Zero results** (`丁度`): an empty card in the existing dashed style: **No results for "丁度"**, followed by the
  applicable suggestions in this order:
  1. "Filters are hiding 6 results. **Clear filters**" (if filters are active)
  2. "Try typing the reading in kana or romaji, e.g. ちょうど" (if the query contains kanji; the example is generic, since the reading of an unknown word is unknown)
  3. "3 results at other levels. **Show all levels**" (if a level filter is active and other levels have hits)
  4. "Search covers this portal's grammar, vocabulary and kanji. It is not a full dictionary."

## 3. Results layout

### 3.1 Page structure (desktop ≥ lg)
The page reuses the lesson grid: `max-w-6xl mx-auto p-4 md:p-6 grid lg:grid-cols-4 gap-6`.
- **Left rail (`lg:col-span-1`, sticky `lg:top-28`)**: `SearchFilters` in the sidebar card style (Type, Level,
  Function). It has the same white card, `bg-slate-100/80` header, and counts in `rounded-full` pills as the lesson list.
- **Main (`lg:col-span-3`)**: status line (`53 results for "ばかり"` plus notes), CategoryChips, then
  `ResultGroup`s, each a white card (`rounded-xl border-slate-200 shadow-sm`).

Below lg, filters collapse to two horizontally scrolling chip rows above the results (type row with counts, level row).
The function filter shows only as an active pill.

### 3.2 Groups
- Order comes from the search service (`groupOrder`, §7.2): single kanji → Kanji first, kana/〜 → Grammar first, English → Vocab first.
- The header is an `<h2>` that reads `Grammar  8 of 12`, with a 3 px left border in the section accent: grammar
  `indigo-500`, vocab `emerald-500`, kanji `rose-500`. These are the colours each section already uses, so learners
  recognise the type at a glance.
- **8 rows** per group in the mixed view. Footer button: `Show all 12 grammar results` sets `more=grammar` (replace)
  and expands in place to 50. After that, `Show 50 more`. With a type filter active, a single group shows 50 at a time.
- Empty groups are omitted, not shown with "0".

### 3.3 Row content (all rows are `<a href>` built from `BASE_URL`)

```
Grammar   〜ものの                                         [N2 · L4]
          Although; even though                       ← meaning, 1 line, truncate
          [Concession / Contrast] [Connective]        ← ≤3 TagBadges, function facet first
          (reason line, only for non-exact tiers)

Vocab     迷う まよう                                       [N3 · L1]
          to lose one's way; to get lost
          → 迷う (dictionary form)                    ← reason line when lemma/deinflected/alias

Kanji     ┌──┐  迷   メイ · まよ・う                         [N3 · L1]
          │迷│      astray, be perplexed
          └──┘      in 迷子 まいご                      ← reason line for compound matches
```

- **Display form** (`title` / `word` / `kanji`): `lang="ja"`, `font-bold`, colour as on the lesson cards
  (`text-indigo-950`, `text-emerald-950`, `text-slate-800`). Stored strings are shown **unchanged**, brackets and all
  (`迷う [道に〜]`, `[お]花見`).
- **Reading**: for vocab, the kana goes inline after the word in `text-slate-500 text-sm`. No ruby, which keeps rows one
  line high and matches the lesson cards, which also print the reading as plain text. For kanji, show up to 2 on'yomi
  and 2 kun'yomi as stored, joined with ` · `. Grammar has no reading.
- **Meaning**: one line, `truncate`, `text-slate-600 text-sm`. For grammar it is `meaning`. When the match was on `summary`
  or `structure`, that field is shown as a second muted line instead of tags (`Structure: Vて-form + いただけませんか`, mono).
- **Level·lesson badge** (`LevelLessonBadge`): `N3 · L12`, `text-[11px] font-bold px-2 py-0.5 rounded-md`, section accent
  (`bg-indigo-100 text-indigo-800` …), the same look as the existing "N3 LEVEL" chip. Right-aligned on desktop, under the
  title on mobile.
- **Collapsed duplicates (Q-UX3)**: one row with several badges in level order (`[N4 · L21] [N3 · L1] [N3 · L15]`).
  **Primary link = the occurrence at `lastLevel` if there is one, otherwise the lowest level** (where it was first taught).
  The primary badge is solid. The others are outlined and are their own links (separate tab stops on mouse/touch, but
  `Enter` on the row always opens the primary).
- **Match highlighting**: `<mark class="bg-amber-100 text-inherit rounded-sm px-0.5">` over the ranges the service
  returns against **display** strings. No ranges means no highlight; the UI never guesses from cleaned keys.
- **Reason line** (ranking made visible, without scores): only for non-obvious tiers.
  `→ 分かる (dictionary form)` · `待たされた → 待つ · causative-passive, past（使役受身・過去）` ·
  `read as きょうしつ` (long-vowel-folded tier: "similar reading") · `also written お酒` · `in 迷子` (compound) ·
  `kanji in 迷惑` (word decomposition) · `collocation: 迷惑を〜`. Style: `text-xs text-slate-500`, with the arrow in `text-indigo-500`.

### 3.4 Filters and URL encoding
`/search?q=ばかり&level=N2,N3&type=grammar&cat=comparison&more=grammar` (all built with `URLSearchParams` on
`import.meta.env.BASE_URL`).

| Param | Values | Notes |
|---|---|---|
| `q` | raw query, as typed | Normalisation is the service's job, and the URL keeps what the user typed. |
| `level` | comma list, `N5`–`N1`, any case | Absent means all levels. Multi-select toggles. |
| `type` | `grammar`, `vocab`, `kanji`, comma list | Absent means all. `tag`/`cat` force `grammar`, and the other types show disabled with the tooltip "Function filters apply to grammar". |
| `tag` | one tag id (`degree-extent`) | Set from TagBadge links and the "All tags" list. |
| `cat` | one alias-category id (`comparison`) | Set from CategoryChips. Expands to its tag ids in the service. `tag` and `cat` are mutually exclusive, and setting one clears the other. |
| `more` | `grammar`, `vocab` or `kanji` | Which group is expanded. Restored on Back. |

Filter changes use `replace`. Unknown values are dropped silently, and the URL is rewritten clean.

## 4. States and interaction

### 4.1 Loading
- **Prefetch** the index on the first `focus` of the header field, `pointerenter` on the mobile icon, or keydown of `/`.
- **First search, cold**: skeleton immediately (3 rows each in 2 cards, `animate-pulse bg-slate-200` bars). After 800 ms
  add "Loading search index (first time only)…". The input never blocks, and queries typed while loading run when it
  arrives. CategoryChips and the browse panel render at once from `tag-taxonomy.json` (already in the main bundle), and
  their counts fade in.
- **Warm**: no spinner. Results swap in place. Stale results stay visible (`opacity-60`) while a new query runs for
  more than 150 ms.

### 4.2 Errors
Index load failure: the lesson error card pattern (dashed `border-red-300`, "Couldn't load search", "Check your connection
and try again.", **Retry**). The header, level pills and tabs keep working (T-45). Worker or query failures use the same card
with "Something went wrong running this search."

### 4.3 Keyboard
| Key | Where | Action |
|---|---|---|
| `/`, `Ctrl/Cmd+K` | anywhere outside input/textarea/contenteditable, and no `aria-modal` dialog open | Focus the header field and select its text |
| `↓` / `↑` | input | Move the active row across all groups, in visual order, and wrap. "Show all" footers are included as items. |
| `Enter` | input | Open the active row (primary link). `Ctrl/Cmd+Enter` opens it in a new tab. **Ignored while `isComposing`.** |
| `Esc` | input | (1) While composing, leave it to the IME. (2) A non-empty query is cleared. (3) An empty query leaves search (Back if the previous entry is in-app, otherwise go to the `lastLevel` lesson). |
| `Tab` | page | Input → category chips → filters → "Show all" buttons. Rows are reached with arrows (combobox pattern), and `Enter` on a focused row link also works for mouse/AT users. |

### 4.4 Accessibility
- The input is `role="combobox"` with `aria-expanded`, `aria-controls="search-results"` and `aria-activedescendant`. Results are
  `role="listbox"`, each group is `role="group" aria-labelledby=<h2 id>`, and each row is `role="option" aria-selected`.
  `lang="ja"` goes on every Japanese span.
- **Live region** (`SearchStatus`, `aria-live="polite"`, visually hidden), updated 500 ms after typing pauses and results settle:
  - `53 results: 8 grammar, 40 vocabulary, 5 kanji.` / `8 results: 8 grammar.` (T-46)
  - with a chip: `… Category available: Comparison, 17 points.`
  - zero: `No results for 丁度.` · loading (once): `Loading search index.` · error: `Search unavailable. Retry button available.`
  - filter change: `Filtered to N2: 3 results.`
- **Focus management**: opening search keeps focus in the header input. Opening a result moves focus to the target card in the
  lesson (§2 F1), so AT users hear its title. Back puts focus in the input with the last opened row active.
  Hide-English masking (§4.6) also uses sr-only text, "translation hidden".
- **Visible focus**: `focus-visible:ring-2 ring-indigo-600 ring-offset-2` (≥ 3:1 on white and on `slate-50`). On the indigo
  header, `ring-white`.
- Reduced motion: no smooth scroll and no highlight pulse (static ring only).

### 4.5 Mobile (< md)
- Tapping the header icon calls `input.focus()` **synchronously in the tap handler** (iOS only opens the keyboard on a
  user gesture), then navigates to `/search`. The header renders search mode (`[←] [input] [×]`, 56 px).
- Input: `text-[16px]` (prevents iOS zoom, as the lesson inputs already do), `enterKeyHint="search"`, `autoCapitalize="off"`,
  `autoCorrect="off"`, `spellCheck={false}`.
- Rows are `min-h-14` and badges `min-h-10` when they are separate links (40 px rule). Type chips stick under the header.
- The keyboard's "Search" key blurs the input, so the results are visible without the keyboard. It does not open row 1.

### 4.6 Hide English mode
Search **matches** English exactly as usual. In results, `meaning`, `summary` and compound meanings render as `••••••••`, the same
mask the lesson cards use, and get no highlight. Kept visible: tag/category labels, the reason line and UI strings, which are
interface rather than translations. Searching an English word in this mode shows the note "English is hidden. Matches
are based on meanings."

| Tags | existing `TagBadge` (add an `href` prop, `hover:underline`, `cursor-pointer`) |

### 5.4 Item highlight in a lesson
On arrival, the target card gets `ring-2 ring-amber-400 ring-offset-2 bg-amber-50/40` for 2.5 s, then fades out
(`transition-[box-shadow,background-color] duration-700`). A small persistent `From search` pill
(`bg-amber-100 text-amber-800 text-[11px] rounded-full`) stays next to the card title until the learner navigates away.
Amber is already the app's "attention" colour (AI examples, missing-section notice) and contrasts with every
section accent. Cards get `scroll-mt-32 max-md:scroll-mt-60` to clear the sticky header (~119 px desktop, ~225 px mobile).

### 7.2 Fields per result (data engineer, `04-data.md`)

**Every hit**
| Field | Type | Used for |
|---|---|---|
| `uid` | string (`n2-grammar-4-1`) | key, `?focus=` |
| `type` | `'grammar' \| 'vocab' \| 'kanji'` | group, row variant |
| `level`, `lesson` | `Level`, number | badge, link `/:level/:type/:lesson` |
| `tier` / `matchKind` | enum: `exact`, `lemma`, `deinflected`, `prefix`, `contains`, `reading`, `reading-folded`, `romaji`, `meaning`, `alias-o`, `variant`, `collocation`, `compound`, `kanji-from-word`, `tag` | reason line, ordering is already done by the service |
| `matchField` | `'title' \| 'structure' \| 'meaning' \| 'summary' \| 'word' \| 'reading' \| 'kanji' \| 'onyomi' \| 'kunyomi' \| 'compound' \| 'tag'` | which second line to show |
| `highlights?` | `{ field, ranges: [start, end][] }[]`, offsets into the **display** string | `<mark>` |
| `deinflection?` | `{ input: string; lemma: string; steps: { en: string; ja: string }[] }` | `待たされた → 待つ · causative-passive, past（使役受身・過去）` |
| `via?` | string (the alias, compound, collocation or source word, e.g. `お酒`, `迷子`, `迷惑`) | `also written …` / `in …` / `kanji in …` |
| `alsoAt?` | `{ uid, level, lesson }[]` | collapsed duplicates (the UI picks the primary per Q-UX3) |

**Grammar**: `title`, `meaning`, `summary?` (only needed when `matchField==='summary'`), `structure?` (only when matched), `tags: string[]` (ids; the UI resolves labels from the taxonomy).
**Vocab**: `word`, `reading`, `meaning`. The lemma is carried in `deinflection.lemma` or `via`.
**Kanji**: `kanji`, `meaning`, `onyomi: string[]`, `kunyomi: string[]` (as stored, separators intact), `compound?: { word, reading, meaning }` when `matchKind==='compound'`.

**Per response**
| Field | Used for |
|---|---|
| `totals: { grammar, vocab, kanji }` (before cap, after filters) | counts, live region, "Show all N" |
| `facetCounts: { type: {…}, level: {…} }` (counts ignoring that facet's own filter) | filter chip counts |
| `groupOrder: Type[]` | group order (the rule stays in the service) |
| `categories: { id, label, count, tagIds }[]` | CategoryChips |
| `queryAs?: string` (kana the romaji was read as) and `didYouMean?: string` | "Searching as きょうしつ", "Did you mean kan'i?" |
| `exactOnly: boolean` | single-kana note |
| `hiddenByFilters: number`, `otherLevelsCount: number`, `queryHasKanji: boolean` | zero-result suggestions |
| `status: 'loading' \| 'ready' \| 'error'` + `retry()` on the source | loading/error states |

Static, no query needed: `listCategories(): { id, label, description, count, tagIds }[]` for the empty-state browse panel and the D3 header.
